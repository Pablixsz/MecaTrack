# Deploying MecaTrack (Docker Hub + Render + GitHub Actions)

Target architecture: GitHub Actions builds and tests every change, publishes the image to Docker Hub
and asks Render to deploy that exact image. Render runs the container (gunicorn, port `$PORT`) next to
a managed PostgreSQL. The frontend is served by the same container, so there is a single public URL.

```
push to main ─► CI/CD: test ─► build ─► push (Docker Hub) ─► deploy (Render deploy hook) ─► /health = new commit
```

The order below matters: Render can only create an image-backed service if the image already exists,
and the `deploy` job needs the Render hook. Following it, the very first pipeline on `main` is green.

## 0. Prerequisites

- Accounts: GitHub (repository `Pablixsz/MecaTrack`), [Docker Hub](https://hub.docker.com), [Render](https://render.com).
- Locally: Docker, and `psql` for the one-time seed (step 5).

## 1. Docker Hub: access token

1. Docker Hub → avatar → **Account settings → Personal access tokens → Generate new token**.
2. Description `github-actions-mecatrack`, permissions **Read & Write**. Copy the token (shown only once).

## 2. Publish the first image (once, by hand)

From the repository root (replace `<user>`):

```bash
docker login -u <user>                       # paste the token as password
docker build --build-arg APP_VERSION=$(git rev-parse HEAD) -t docker.io/<user>/mecatrack:latest .
docker push docker.io/<user>/mecatrack:latest
```

After this, every push to `main` publishes new images automatically.

## 3. Render: database + web service

**Option A — Blueprint (recommended).** Edit `render.yaml`, replace `<DOCKERHUB_USERNAME>`, commit and push the
branch. In Render: **New → Blueprint**, connect the repository, select the branch, **Apply**. It creates:

- `mecatrack-db`: PostgreSQL 16, free plan.
- `mecatrack`: web service from `docker.io/<user>/mecatrack:latest`, health check `/health`,
  `DATABASE_URL` linked to the database, `SECRET_KEY` and `JWT_SECRET_KEY` generated by Render, `PROXY_FIX_HOPS=1`.

**Option B — by hand.**
1. **New → Postgres**: name `mecatrack-db`, database `taller_mecanico`, PostgreSQL 16, plan Free. Create.
2. **New → Web Service → Existing image**: `docker.io/<user>/mecatrack:latest` (keep `docker.io/`). Plan Free.
3. **Environment**:
   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the database's **Internal Database URL** |
   | `SECRET_KEY` | *Generate* |
   | `JWT_SECRET_KEY` | *Generate* |
   | `FLASK_ENV` | `production` |
   | `PROXY_FIX_HOPS` | `1` |
   | `GEMINI_API_KEY`, `GEMINI_MODEL` | optional |
4. **Settings → Health Check Path**: `/health`.

On the first start the container's entrypoint runs `flask db upgrade` (creates the tables). Render gives the
URL, e.g. `https://mecatrack-xxxx.onrender.com`. Check: `curl https://<your-url>/health` →
`{"database":"ok","status":"ok","version":"…"}`.

> `postgres://` URLs: Render hands out `postgres://…`; the app rewrites it to `postgresql://` (SQLAlchemy 2.0).

## 4. GitHub secrets

Repository → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Value |
|---|---|
| `DOCKERHUB_USERNAME` | your Docker Hub user |
| `DOCKERHUB_TOKEN` | the token from step 1 |
| `RENDER_DEPLOY_HOOK_URL` | Render → service `mecatrack` → **Settings → Deploy Hook** (`https://api.render.com/deploy/srv-…?key=…`) |
| `PUBLIC_URL` | `https://<your-url>.onrender.com` (no trailing slash) |

The deploy hook URL is a secret: anyone who has it can trigger deploys.

## 5. Demo data (manual, never automatic)

Production never seeds itself. For the demo, load `database/seed.sql` once into the Render database
**after** the app has started (tables must exist). Render free has no shell, so run it from your machine
with the **External Database URL** (Render → `mecatrack-db` → Connect):

```bash
psql "<External Database URL>?sslmode=require" -v ON_ERROR_STOP=1 -f database/seed.sql
```

(mechanic), `laura.cliente@gmail.com` (client), `admin@tallermecanico.com` (admin).
Running it twice fails on unique constraints (on purpose: it never overwrites data).

## 6. First automatic deploy

Merge `mecatrack-final` into `main` (pull request). The `CI/CD` workflow runs the four stages; the `deploy`
job calls the hook with `imgURL=docker.io/<user>/mecatrack:sha-<short>` and waits until
`https://<your-url>/health` reports the new commit. Verify end to end:

```bash
backend/venv/bin/python scripts/e2e_flow.py --base-url https://<your-url> --out docs/evidence --prefix p5-render
```

## Free plan limitations (checked on 2026-11-09 in render.com/docs/free)

| Limitation | Effect on the demo | Mitigation |
|---|---|---|
| The web service **spins down after 15 min** without traffic; waking up takes **about 1 minute** | The first request of the demo is slow | Open `/health` 2–3 minutes before presenting |
| **Free PostgreSQL expires 30 days after creation** (then 14 days of grace before deletion); 1 GB; one free DB per workspace | Creating it too early means it may be gone on demo day | Create the database less than 30 days before the demo, or upgrade it (paid) for that month |
| No shell and no persistent disk; local files are lost on restart/redeploy | Downloaded open-data snapshots (`/api/v1/market/refresh`) disappear | Refresh them at the start of the demo |
| 750 free instance hours per month per workspace | Enough for one always-on service | — |
| In-memory rate limits and JWT blocklist | Reset on restart/spin-down (a logged-out token works again until it expires, max 15 min) | Documented trade-off; Redis would fix it (paid) |

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Deploy hook returns **400** | `imgURL` does not match the service image except for the tag: the service must use `docker.io/<user>/mecatrack:latest` exactly. |
| `/health` returns **503** | The app runs but cannot reach PostgreSQL: check `DATABASE_URL` (Internal URL) and that the DB is not expired. |
| Container exits at start: `JWT_SECRET_KEY is required` | Add `JWT_SECRET_KEY` in Environment. |
| `deploy` job times out | Check Render → Events/Logs; a cold free instance plus image pull can take several minutes. |
| Login answers **429** | Login rate limit (5/min per client IP): wait for `Retry-After`. |
